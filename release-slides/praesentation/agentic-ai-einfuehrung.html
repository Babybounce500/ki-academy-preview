Chatbot oder Agent?

Chatbot

  • Du fragst, er antwortet
  • Ein Schritt, dann wartet er
  • Wirkt nur im Gespräch
  • Du führst das Ergebnis selbst aus

Agent

  • Du gibst ein Ziel, er plant selbst
  • Mehrere Schritte in einer Schleife
  • Nutzt Werkzeuge: Suche, Dateien, APIs, Code
  • Prüft Zwischenergebnisse und macht weiter

Die Schleife als Code

python
def run_agent(ziel, tools, max_schritte=8):
    verlauf = [{"role": "user", "content": ziel}]
    for _ in range(max_schritte):
        antwort = llm(verlauf, tools)          # Modell entscheidet
        if antwort.tool_call is None:
            return antwort.text                # fertig
        ergebnis = tools[antwort.tool_call.name](**antwort.tool_call.args)
        verlauf.append({"role": "tool", "content": ergebnis})
    return "Abbruch: Schrittlimit erreicht"

Vereinfacht. llm() steht für den Aufruf eines beliebigen Modells mit Werkzeugunterstützung.

Ein Werkzeug beschreiben

json
{
  "name": "wetter_abfragen",
  "description": "Liefert das aktuelle Wetter für eine Stadt",
  "input_schema": {
    "type": "object",
    "properties": { "stadt": { "type": "string" } },
    "required": ["stadt"]
  }
}

Das Modell wählt Werkzeuge anhand ihrer Beschreibung. Gute Beschreibungen sind der halbe Erfolg.

MCP: ein Standard für Werkzeuge

Das Model Context Protocol (MCP) legt fest, wie ein Agent Werkzeuge und Datenquellen anspricht. Statt für jedes Programm eine eigene Anbindung zu bauen, spricht der Agent mit jedem MCP-Server auf dieselbe Weise. Das senkt den Aufwand und macht Werkzeuge austauschbar.

10 / 18

A2A: Agenten sprechen miteinander

Während MCP einen Agenten mit Werkzeugen verbindet, regelt A2A (Agent-to-Agent) die Zusammenarbeit zwischen Agenten, auch über Anbietergrenzen hinweg. So kann ein Recherche-Agent einem Schreib-Agenten Arbeit übergeben, ohne dass beide vom selben Hersteller sein müssen.

Wann lohnt sich ein Agent?

Gut geeignet

  • Das Ergebnis lässt sich prüfen (Tests, Abgleich)
  • Klarer Rahmen und klares Ziel
  • Schritte sind rückgängig zu machen
  • Wiederkehrende Aufgaben mit festem Muster

Vorsicht

  • Unklares Ziel oder wechselnde Regeln
  • Nicht umkehrbare Aktionen: Zahlungen, Löschen, Versand
  • Sensible Daten ohne klare Zuständigkeit
  • Ergebnisse, die niemand prüfen kann
13 / 18

Sicherheit: fünf Leitplanken

  1. 1
    Minimale Rechte

    Nur die Werkzeuge und Daten, die die Aufgabe braucht

  2. 2
    Freigabe bei Risiko

    Zahlungen, Löschen, Versand nur nach menschlicher Bestätigung

  3. 3
    Limits setzen

    Schrittzahl, Laufzeit und Kosten begrenzen

  4. 4
    Protokollieren

    Jede Aktion nachvollziehbar speichern

  5. 5
    Fremde Inhalte misstrauen

    Webseiten, Mails und Dokumente können versteckte Anweisungen enthalten

Modelle wählen: Kriterien statt Namen

  • ✓Teste an deiner eigenen Aufgabe, nicht an fremden Ranglisten
  • ✓Kosten pro erledigter Aufgabe, nicht pro Anfrage
  • ✓Geschwindigkeit: kleine Modelle für einfache Schritte
  • ✓Kontextlänge und Werkzeugzuverlässigkeit
  • ✓Datenschutz, Standort und Vertrag des Anbieters
