# Decorators für clean code
from functools import wraps
import time

def timer(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start:.2f}s")
        return result
    return wrapper

@timer
def slow_function():
    time.sleep(1)
    return "done"

# Async Python für I/O
import asyncio
import aiohttp

async def fetch_vibe(session, url):
    async with session.get(url) as response:
        return await response.json()

async def main():
    async with aiohttp.ClientSession() as session:
        vibes = await asyncio.gather(
            fetch_vibe(session, 'https://api.com/1'),
            fetch_vibe(session, 'https://api.com/2'),
        )
    return vibes

    model="claude-sonnet-4-5-20250929",

        print(text, end="", flush=True)

The 5-Level Iteration Framework

Level 1: Skeleton (MVP)

Ziel: Funktionalität beweisen - "Does it work?"

Claude Prompt:

"Build a basic [feature] with:
- Core functionality only
- No styling (minimal CSS)
- No error handling yet
- Hard-coded data is fine
- Just prove the concept works"

Output: Funktionierender Prototype in 5-10 Minuten

Level 2: Flesh (Features)

Ziel: Alle Features implementieren - "Does it do everything?"

Claude Prompt:

"Enhance the previous code with:
- All CRUD operations
- State management (useState/context)
- Basic validation
- Loading states
- Keep existing structure"

Iteration Tips:

  • Eine Feature-Gruppe nach der anderen
  • Test nach jedem Add
  • Commit after each working feature

Level 3: Muscle (Quality)

Ziel: Code Quality steigern - "Is it clean & maintainable?"

Claude Prompt:

"Refactor this code focusing on:
- Extract reusable components/functions
- Add TypeScript types
- Improve naming conventions
- Add proper error handling
- Add input validation
- Remove code duplication
- Follow [framework] best practices"

Quality Checklist:

  • ✅ No code duplication (DRY principle)
  • ✅ Functions under 20 lines
  • ✅ Descriptive variable names
  • ✅ Error boundaries everywhere
  • ✅ Proper type safety

Level 4: Skin (UX/UI)

Ziel: User Experience optimieren - "Is it delightful?"

Claude Prompt:

"Polish the UI/UX with:
- Modern, cohesive design system
- Smooth animations & transitions
- Loading skeletons
- Empty states with helpful messages
- Success/error toast notifications
- Keyboard shortcuts
- Mobile-responsive layout
- Dark mode support
- Accessibility (ARIA labels, focus states)"

UX Enhancement Tricks:

  • Micro-interactions: Button hover effects, subtle bounces
  • Skeleton screens: Statt spinner beim Laden
  • Optimistic UI: Update UI sofort, sync später
  • Contextual help: Tooltips, placeholder text
  • Smooth transitions: Zwischen states & pages

Level 5: Performance (Optimization)

Ziel: Speed & Efficiency maximieren - "Is it FAST?"

Claude Prompt:

"Optimize for performance:
- Add React.memo / useMemo / useCallback
- Lazy load components
- Debounce user inputs
- Virtualize long lists
- Optimize images (lazy loading, proper formats)
- Minimize bundle size
- Add service worker for caching
- Implement code splitting"

Performance Wins:

  • Code Splitting: const Component = lazy(() => import('./Component'))
  • Image Optimization: WebP format, lazy loading
  • Debouncing: Search inputs, resize handlers
  • Memoization: Expensive calculations
  • Virtual Scrolling: Für lange Listen (react-window)

Common Iteration Mistakes zu vermeiden

❌ Don't: Premature Optimization

Nicht in Round 1 über Performance nachdenken!

// ❌ BAD - zu früh
"Build a todo app with:
- Virtualized list
- Memoized everything  
- Service worker
- Code splitting"

// ✅ GOOD - schrittweise
Round 1: "Build basic todo app"
Round 2: "Add features"
Round 3: "Now optimize performance"

❌ Don't: Over-Engineering

Keep it simple bis du complexity brauchst!

// ❌ BAD - unnecessary complexity
"Create enterprise-grade state management 
with Redux, saga, normalizr for this 
simple counter app"

// ✅ GOOD - right-sized
"Use useState for this simple counter.
We'll upgrade to context if needed later."

❌ Don't: Random Changes

Jede Iteration braucht ein klares Ziel!

// ❌ BAD - unfocused
"Make it better"

// ✅ GOOD - specific goal
"Improve form validation:
- Add real-time feedback
- Show specific error messages
- Highlight invalid fields"
